# 僚机 Wingman · v2.x UI 改版上下文简报（事实基线）

> 本文件由主理人汇编，只记录**现状事实与硬约束**，不含设计结论。
> 视觉/体验/工程结论分别由三位成员产出。

## 0. 本轮边界（用户原话）

「既然是 2.0 了，再优化一下 ui，图标再优化一下，要求风格统一，元素一致，
应用界面合理，文字描述这些也优化一下，安装界面别忘了，**先出预览经过我确认后再打包**。」

- 当前实际版本 **v2.1.1**（用户口中的「2.0」指 2.x 大版本线）。
- **只出预览**：禁止修改 `src/` 与 `installer/` 里的生产代码，禁止 PyInstaller 打包、
  禁止覆盖 `app/` 生产目录、禁止部署、禁止改注册表/计划任务。
- 交付物全部落在 `design/v2-ui/`。
- 预览必须同时覆盖「设置面板」与「安装界面」，并给出新旧图标对照。

## 1. 技术栈与可实现性硬约束

| 项 | 事实 |
|---|---|
| 设置面板 | Python 3.8 + Tkinter，**全部控件 Canvas 自绘**（`src/settings_gui.py`），无 ttk |
| 安装器 GUI | Python 3.8 + `ttk.Style('vista')` 原生控件（`installer/setup_abg.py:802-940`），**风格与面板割裂** |
| 可用绘图原语 | `create_line / polygon / oval / arc / rectangle / text`，无渐变、无阴影、无抗锯齿、无 SVG 渲染、无图片缩放（ico 除外） |
| 色彩 | **纯中性灰阶，零彩色**。任何方案都必须能只用 THEMES 里的 10 个色 token 表达 |
| 主题 | `ui_theme = light / dark`，切换时全控件重建；两个主题必须结构对称 |
| DPI | 96 / 120 / 144 / 168 / 192 / 240 六档，所有尺寸走 `px(v)` 等比缩放；图标按 24×24（品牌盾 64×64）设计坐标乘 `size/24` |
| 字体 | `Microsoft YaHei UI` → `Microsoft YaHei` → `Segoe UI`，负号像素字号，按 DPI 显式重设 |
| 现有设计系统参考 | `design/ui-prototype.html`（58 KB，已有 Design System 页 + 安装程序第二版预览，可复用其 token） |
| 图标生成器 | `design/generate_icons.py`：零依赖扫描线栅格化 → 7 档 PNG → ICO；几何唯一来源 `design/abg-mark.svg`（盾 + 镂空上箭头） |

**关键**：新图标必须是「少量直线/圆弧/多边形」就能画出来的形状，
不能要求抗锯齿、贝塞尔曲线、渐变或半透明叠加，否则 Tkinter 落地会变形。

## 3. 界面 A：设置面板（真实结构）

无边框主窗口，标题栏由系统绘制（用户截图里是深色标题栏 + 自绘黑色客户区）。

```
┌ 标题栏：盾 16px + "僚机 Wingman" + 最小化/最大化/关闭 ┐
│ [盾 28] 僚机 Wingman                    [＋ 20] [齿轮 20] │  ← 头部
│ ─────────────────────────────────────────────────── │
│ [图标 22] 名称（tooltip 悬停 320ms）  [开关 40×22] [垃圾桶 18] │  × 4 行
│ ─────────────────────────────────────────────────── │
```

- 头部：`＋` 在齿轮**左侧**（pack side='right' 的先后决定），两者都是 20px 线性图标 + 9×7px 内边距的透明按钮，hover 才出底色。
- 功能行：图标 22px、名称 `f_head`（粗体）、40×22 胶囊开关（纯 Canvas 自绘）、垃圾桶 18px。
- **行数据完全来自插件注册表**，当前 4 个（顺序 = order）：

| order | id | name | icon | version | requires_admin | 简介（tip，现文） |
|---|---|---|---|---|---|---|
| 10 | afterburner | 小飞机关联启动 | `link` | 2.0.0 | 否 | 检测到游戏启动时自动拉起 MSI Afterburner（含 RTSS 监控），游戏退出后按配置一并关闭。切换即时生效。 |
| 15 | gamepp | 游戏加加联动 | `link` ← **与上一行图标重复** | 1.0.0 | 否 | 检测到游戏启动时自动拉起游戏加加（GamePP），游戏退出后只关闭本次会话新拉起的进程。主程序路径留空会自动探测，切换即时生效。 |
| 20 | ace | ACE 防护 | `shield` | 2.0.0 | **是** | 游戏运行中把 ACE 反作弊进程的 CPU / 磁盘 IO 降到最低优先级；退出后经四道闸门停服务、清残留。运行时限速 + 退出后清理，不写内存、不注入、不加载驱动，随时可还原。 |
| 30 | popup | 弹窗关闭 | `block` | 2.0.0 | 否 | DemoGame / WeGame 退出后弹出的直播窗口：会话期间窗口一露面就提前关闭，全退后再清理 ClientBrowser 后台进程树，避免常驻。 |

- 零插件态：一行灰字「未加载任何插件 · 把插件目录放进 plugins\ 后重开本面板」。
- 只读态（未提权且装在 Program Files）：＋/垃圾桶/三个开关/停止守护/重扫/开机自启置灰，状态行显示「需要管理员权限」。置灰用 `t3` 灰阶。
- 齿轮菜单（无标题栏浮层，贴齿轮右下，1px 分隔线分组），行数由注册表算：`11 + 1 + 插件数 + 1`：
  - 守护状态（右侧 hint「运行中 / 未运行」）／启动守护／停止守护／开机自动启动守护（右开关）
  - ─ 重扫游戏库／查看运行日志／编辑配置文件
  - ─ 插件（hint「共 N 个」）／每插件一行（hint 如 `v2.0.0 · 正常 · 已启用 · 需要管理员`）／打开插件目录
  - ─ 纯白（勾选）／纯黑（勾选）
  - ─ 保存设置／关闭（hint「Esc」）
  - 底部小字 `v2.1.1 · 开关即时生效`
- Tooltip：反色（inv / invfg）小浮层，悬停 320ms 出现，移开/点击/切主题收起。
- 状态提示词表：`正常 / 运行异常 N 次 / 加载失败 / 需要更新的内核 / ID 冲突 / 已禁用 / 已启用 / 需要管理员`。
- 弹框文案现状（全是技术黑话）：`设置已写入 config.json。守护会在 2 秒内自动加载，无需重启。`、
  `添加插件（.zip 包）`、`插件 %s（%s v%s）已经装过了。覆盖会先把旧目录备份到 %LOCALAPPDATA%\Wingman\`、
  `目录会移进备份区（不硬删），守护 2 秒内热重载。`

## 4. 界面 B：安装程序（真实结构）

`installer/setup_abg.py:gui()`，窗口 660×520（按 DPI 缩放），最小 600×460，**ttk 原生 vista 主题**：

```
标题栏：僚机 Wingman 安装程序 2.1.1
[大标题 22px bold] 僚机 Wingman 安装程序
[副标题 13px #555] 小飞机关联启动 · ACE 防护 · 弹窗关闭      ← 写死三功能，实际四个插件
安装目录 [Entry ........................] [浏览…]
☑ 开机自动启动守护（计划任务）
☑ 安装完成后立即启动
小飞机：F:\...\MSI Afterburner\MSI Afterburner.exe（自动探测） / 未找到，装完后可在设置面板或 config.json 里指定
安装过程
┌ #f4f4f4 灰底 Text，Consolas 12px，9 行日志 ┐
└──────────────────────────────────────────┘
                              [退出] [安装]   ← 按钮在右下
```

- 安装中：`安装` 变「重新安装」，成功弹 `完成 / 安装完成。\n\n目录：%s`，失败弹 `失败 / repr(e)`。
- 静默参数：`/S /DIR= /AUTO= /LAUNCH= /NOTASK /UNINSTALL /GUITEST`，GUI 只是其中一条路径。
- 现有设计稿 `design/ui-prototype.html` 里已有一版「安装程序 第二版预览」的 HTML mock；
  但真实安装器**没按那版实现**。
- 安装器还有卸载流程（`/UNINSTALL`）与 UAC 提权流程，预览可只覆盖首屏 / 安装中 / 完成三态。

## 5. 图标清单（`src/settings_gui.py:685-820`，`Glyph`）

24×24 设计坐标（品牌盾 `mark` 用 64×64），线宽 `lw = 1.7` 单位：

| kind | 画法 | 用途 |
|---|---|---|
| `mark` | **实心**盾 + 镂空上箭头 | 品牌（窗口/托盘/安装包） |
| `link` | 实心双箭头 | 小飞机 / 游戏加加（重复） |
| `shield` | 实心盾 + 镂空勾 | ACE 防护 |
| `block` | 实心圆角方 + 斜杠 | 弹窗关闭 |
| `gear` | **实心** 8 齿轮 + 镂空圆 | 设置 |
| `dot` | 实心小圆 | 菜单分组标题 |
| `play` / `stop` | 实心三角 / 方 | 启动 / 停止守护 |
| `boot` | 线性圆 + 竖线 | 开机自启 |
| `rescan` | 线性弧 + 实心箭头 | 重扫游戏库 |
| `log` / `cfg` | 线性 | 日志 / 配置 |
| `sun` / `moon` | 线性 / 实心 | 主题 |
| `check` / `close` | 实心勾 / 线性叉 | 保存 / 关闭 |
| `plus` / `trash` | 线性 | 添加 / 删除插件 |

**已知不一致（用户说的「风格统一、元素一致」）**：
1. 功能图标里 `link / shield / block / gear / play / stop / moon / check` 是实心填充，
   `boot / rescan / log / cfg / sun / close / plus / trash` 是线性描边 —— 两套语言混用。
2. 实心图标的「镂空」用当前背景色画，hover 时需要 `set_bg()` 重绘，容易与行底色不一致。
3. `link` 同时代表「小飞机」和「游戏加加」，语义无法区分；新增插件只能复用已有 4 个图标名。
4. 品牌盾箭头是**上箭头**（加力起飞），与「僚机/守护」语义弱；16px 下上箭头与盾边缘容易糊。
5. 图标光学尺寸不齐：`link` 占满 21.5 宽、`shield` 只有 16.4 宽、`block` 18 宽。
6. 安装器完全用系统控件，**没有任何自绘图标**，与面板的品牌体验断开。

## 6. 文字现状（用户要求「文字描述也优化」）

问题集中在：技术黑话外露（`config.json`、`pid`、`plugins\`、`.zip`、`热重载`、
`ClientBrowser`、`ACE 反作弊进程`、`%LOCALAPPDATA%`、`计划任务`、`v2.0.0`）、
同一动作多种叫法（`关闭 / 退出 / 停止`、`添加 / 安装`、`删除 / 移进备份区`）、
菜单项长短不一（`开机自动启动守护` 9 字 vs `关闭` 2 字）、
安装器副标题写死旧三功能、错误弹框直接 `repr(e)`。
