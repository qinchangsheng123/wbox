# 僚机 Wingman v2.x · 体验规范与全量文案（Phase 2）

> 只定信息架构、交互流程与全量界面文案，不含视觉 / 配色 / 图标结论，不含代码。覆盖设置面板（Canvas 自绘）与安装程序（660×520 独立窗口）。下表「现文」为定位用节选，完整原文见 `00-brief.md`；「新文」列是 Phase 3 `preview.html` 的唯一文案来源。

## 0. 结论先行

这轮不是「润色」，而是**把实现细节从用户眼前拿走，把「下一步」补进每个状态**。五条最关键改动：① 安装器副标题不再写死功能清单；② 错误框从 `repr(e)` 换成「发生了什么 + 你能做什么」；③ 六个内部名词（`config.json`、`plugins\`、`%LOCALAPPDATA%`、`.zip`、`热重载`、`计划任务`）退出界面；④ 安装中「重新安装」改为禁用的「安装中…」；⑤ 覆盖 / 卸载确认框删路径与版本号，按钮改用具体动词。

## 1. 文案总原则

**语气**：简洁、平视、不吓人、不承诺做不到的事。用「你」，不堆「请」，不用「严重 / 非法」等审判词；讲结果不讲实现；不写「随时可还原」「永不」「2 秒内」这类绝对或时间承诺——做不到的数字比不写更伤信任。

**术语表**（左列不得出现在任何界面文字、Tooltip、弹框、日志首行）

| 禁止 | 替代 |
|---|---|
| `config.json` | 设置 / 设置文件 |
| `plugins\`、插件目录路径 | 插件文件夹（不写路径） |
| `%LOCALAPPDATA%\Wingman\` | 备份（旧版本先备份，之后可找回） |
| `.zip` / 包 / manifest | 插件文件（仅文件过滤器保留 `*.zip`） |
| 热重载 / 2 秒内自动加载 | 改动立即生效 / 无需重启 |
| `ClientBrowser` / 进程树 / pid | 后台程序 / 残留的后台程序 |
| `ACE 反作弊进程` / CPU / 磁盘 IO / 四道闸门 / 不写内存不注入 | 反作弊程序 / 降低对电脑资源的占用 |
| `计划任务` | 不出现，只说「开机自动运行」 |
| `repr(e)` / 异常对象 / traceback | 一句人话 +「详情可查看日志」 |
| `v2.0.0`（插件版本号） | 界面不显示，只留应用版本 `v2.1.1` |

产品名（MSI Afterburner、游戏加加、ACE）保留——用户认得；要去掉的是缩写堆叠与实现细节。

**动词统一表**

| 动作 | 统一用 | 不再用 |
|---|---|---|
| 结束后台守护 | 停止 | 关闭、退出 |
| 结束窗口 / 安装器 | 退出 | 关闭、停止 |
| 收起面板 / 菜单 / 弹框 | 关闭 | 退出 |
| 放入插件 | 安装 | 添加、装入 |
| 移除插件 | 卸载 | 删除、移进备份区 |
| 开 / 关功能 | 启用 / 关闭 | 打开、开启、停用 |
| 重新检测游戏 | 重新扫描 | 重扫、刷新 |
| 程序跑起来（安装器勾选项） | 运行 | 启动 |
| 写入设置 | 保存 | 写入、应用 |

状态词收敛：`加载失败→未能加载`、`需要更新的内核→需要更新`、`ID 冲突→名称重复`、`需要管理员→需管理员`；`正常 / 运行异常 N 次 / 已启用 / 已关闭` 保留。

**句长与换行**：按钮 2–4 字；菜单项 4–6 字（hint 不计）；弹框标题 2–4 字；Tooltip ≤ 2 行、约 40 字上限，**写稿时压够，不靠界面省略号**；正文单段 ≤ 2 句；路径、版本号、技术名不进首句。Tooltip 结构 =「做什么（结果）」+「何时生效 / 前提」，不写实现。

**数字与版本号**：应用版本统一 `vX.Y.Z`，只出现在菜单底部小字与安装器页面，不进标题栏；插件版本号不在界面出现；数量写「共 N 个 / 已找到 N 款游戏」；不写秒数、百分比、进程数。

**错误公式**：`标题（发生了什么，2–4 字）+ 正文（事实 + 用户下一步）+ 可选（去哪看详情）`。按钮给「重试 / 关闭 / 查看详情」，不给裸「确定」。涉及数据时主动说明「文件没有被改动 / 旧版本已备份，之后可找回」。原始异常只放「查看详情」。

## 3. 信息架构与流程

**头部主次**：主操作 = 每行开关（高频、即时、可逆，L0）；次操作 = ＋ 安装插件（低频，需选文件 + 确认）；管理入口 = 齿轮（收纳低频全局动作）；危险操作 = 垃圾桶（行内、L2 确认、可找回）。权重对应：开关最显眼，＋ / 齿轮为 hover 才出底的透明按钮，垃圾桶最小且仅 hover 显现以降低误触。

**确认层级**（影响面递增）：L0 开关 / 主题 / 查看日志，不确认；L1 保存设置 / 重新扫描，状态行或轻提示，不弹模态框；L2 卸载插件 / 覆盖安装 / 停止守护，二次确认；L3 内置插件卸载 / 权限不足，再加风险或原因说明。危险确认三段式：标题（动作 + 具体对象）→ 正文（后果 + 可逆性）→ 按钮（「卸载」「覆盖安装」，不用「确定 / 是」，形成最后一道防错）。

**四种状态给用户看什么**：只读态——＋ / 垃圾桶 / 开关 / 启动停止 / 重扫 / 开机自启置灰，但齿轮菜单、日志、主题、关闭仍可用，状态行两行说明「为什么 + 怎么办」，不整屏死掉；加载失败态——保留名称、开关置灰、显示「未能加载」，Tooltip 指向日志；零插件态——两行提示 + ＋ 保持可用，不留死路；异常态——行内「运行异常 N 次」+ 自救 Tooltip，不弹框。**任何 `t3` 置灰控件旁必须有可见解释文字**。

**安装器状态流**

```
首屏（可配置） ──安装──▶ 安装中（只读 + 进度） ──┬─▶ 完成 ──▶「完成」退出
  │  目录 / 两个选项 / 探测结果 / 日志占位        │        └─▶ 失败 ──▶「重试」「查看详情」「退出」
  └─退出（二次确认）                   中文步骤短句 + 按钮禁用
卸载：入口 ──▶ 确认（是否保留设置）──▶ 卸载中 ──▶ 完成
```

每态可见信息：首屏 = 目录、勾选项、探测结果、日志占位、双按钮；安装中 = 中文步骤短句、按钮禁用、退出需确认；完成 = 装到哪 + 下一步 + 单一「完成」；失败 = 原因摘要 +「文件没有被改动」+ 重试 / 详情 / 退出。状态变化不能只靠按钮文字，标题与日志首行同步切换。

**高风险交互与降级方案**

| 高风险点 | 降级方案 |
|---|---|
| 覆盖安装：以为旧插件丢了 | 先备份 + 确认框写「之后可找回」+ 失败回滚备份 |
| 卸载内置插件：可能无法恢复 | 追加风险说明，或降级为不可卸载、只给开关 |
| 停止守护：插件静默失效 | 确认框写后果，hint 明确「未运行」 |
| 失败抛 repr(e) | 人话 + 可逆说明 + 重试，堆栈只放「查看详情」 |
| 权限不足整屏置灰 | 两行说明 + 菜单 / 日志 / 主题仍可用 |
| 高 DPI 下 hint、路径被挤掉 | hint 先省略、路径悬停看全；写稿时压够字数 |

## 4. 可用性与无障碍

**键盘**：Tab 顺序 = ＋ → 齿轮 → 各行开关 → 各行卸载按钮；菜单打开时焦点移入首项，Esc 关闭并把焦点还给齿轮；Enter / Space 操作当前焦点；弹框焦点默认落在**安全按钮**（取消 / 关闭），Enter 绝不触发危险动作。无鼠标专属操作。

**焦点可见**：Canvas 自绘无原生焦点框，须用 `fg` 色 1px 焦点环 + 2px 外偏移显式绘制，dark 用 `inv` 反色成对实现，且不被 hover 底色覆盖。

**置灰必配解释**：只读态两行、失败态 Tooltip、安装中按钮旁「正在安装，请稍候」；禁止只有灰、没有话。

**DPI 96–240**：文字与容器都走 `px(v)` 等比，按最长串（「开机自动运行守护」9 字、安装路径）留 1.2× 余量；菜单 hint 右对齐、与菜单项留 ≥ 12px，高 DPI 下 hint 先截断而非挤掉菜单项；Tooltip 固定最大宽度、强制 ≤ 2 行（写稿压够，不靠省略）；禁止写死文字绝对像素坐标。

**对比度（现有 10 个灰阶 token）**：`fg/bg` 双主题 21:1 ✓；`t2/bg` 浅 ≈ 7:1、深 ≈ 10:1 ✓；`t3/bg` 浅 ≈ 4.54:1、**仅勉强过 WCAG AA 4.5:1**，深 ≈ 5.9:1 ✓；Tooltip 反色 21:1 ✓；`border/bg` ≈ 4.5:1 满足非文本 3:1 ✓；`line` ≈ 1.2:1 仅装饰、不承载信息 ✓；hover / active 底上文字 > 19:1 ✓。**结论：`t3` 不得再降灰、不得承载正文**，只用于版本号、状态词与置灰，且另配解释文字做语义补偿。双主题对称：同位置同字号同字数、同截断策略，焦点环与 Tooltip / 菜单 / 弹框三处反色浮层成对实现。

**色弱与读屏**：状态不能只靠颜色——开关须同时有「已启用 / 已关闭」文字或形状差异。Tkinter Canvas 无原生语义，第一阶段底线 = 每个可交互控件有可读名称（如「弹窗拦截，已启用，开关」）+ 键盘全可达 + 焦点环可见；无法接入系统读屏时，至少保证文字不靠颜色单独表意。
