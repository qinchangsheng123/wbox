Skins

皮肤是插件，但不跑代码

设置里多一页「外观」：已装皮肤按卡片列出，缩略图就是它穿在窗口上的样子，右上一枚勾表示当前在用。 皮肤与功能插件同一个安装入口，但两者边界不同——功能插件是守护进程里的 Python，皮肤只有 skin.json 和位图， 面板加载、只换外观，不动任何一行逻辑。

为什么皮肤不做成"插件进程"。功能插件要拿到游戏进程、要提权、要读写配置，跑在守护进程里是合理的； 皮肤只影响画出来的像素，把它关在数据层里，第三方皮肤就永远不可能因为一行代码把守护搞崩。 皮肤包里出现 .py / .dll / .exe 一律拒绝安装，这条是硬规则。

Skin 01 · Liquid Glass

液态玻璃：效果换成本，成本是明确的

这一版就是 v3.4.0 的效果，原样保留成内置皮肤。它贵在三个地方：整窗磨砂位图、 每行自绘控件、悬停与弹出的过渡定时器。三样都是可见的、可数的，不是玄学。

它的三笔开销

  • 整窗位图 3 张：磨砂背景 640×332、圆角遮罩 640×332、阴影 680×372，合计 640×332×4 + 640×332×4 + 680×372×4 = 2.6 MB（Tk 内部每像素 4 字节）。tkinter 没有 blur，只能启动时截一次桌面、模糊一次、缓存住。
  • 每行 4 个自绘元素：发丝线、图标、名称、开关各一个 canvas item，5 行就是 20 个；改一次颜色就重画一次。
  • 过渡定时器：悬停 160 ms、弹出 200 ms，各一条 after 链。静止时归零，动画期间约 60 帧。

它换到了什么

半透明的层次感让 640×332 的小窗口看起来有纵深；圆角与阴影让窗口浮在桌面上而不是贴上去。

代价可接受的前提是面板不是常驻窗口——它是用户点开、改两下、关掉的窗口，不是每秒都在动的东西。 这也是为什么它适合当默认皮肤，而不适合当唯一皮肤。

Skin 02 · Plain

极简：能省的全省，只留功能

它不是为了"另一种风格"而存在，是为了"最不吃性能"而存在。四刀砍下去：不贴任何位图、不画任何圆角、 不起任何动画、不开任何浮层窗口。剩下全是原生控件，系统怎么画就怎么画。点一行，设置就在那一行底下摊开。

省在哪（每一条都能数）

  • 位图 0 张：背景是 #FFFFFF 一个颜色，没有任何 PhotoImage。
  • 圆角 0、阴影 0：方角省掉 mask 位图与 SetWindowRgn 调用，阴影省掉一次整窗 alpha 合成。
  • 自绘元素 0：标题、行、开关全是原生控件，Tk 自己维护，改状态只重画那一块。
  • 定时器 0：悬停只换底色，不做 160 ms 过渡；展开收合立刻生效。空闲时进程里没有一条 after 链。
  • 浮层窗口 0：设置项插在行下方，不新建 Toplevel，少一个窗口句柄与一套 z 序。
  • 像素更少：行高 44（玻璃 52）、字号 13（玻璃 15）、图标 16（玻璃 22），一屏少画约三成。

它放弃的

没有玻璃的通透感、没有圆角、没有弹出动画——这三点是明确的取舍，不是没做完。

它仍然保留品牌：WBOX 字标还在左上，图标还是那枚填充 W，只是尺寸降到 16 并改单色。

选它的人应该是因为「这破电脑风扇本来就响」，而不是因为它好看。

Cost

两套皮肤的账，逐项列出来

下面每一行都是设计阶段能锁死的量：位图几张、元素几个、定时器几条。 落到代码里这些数直接决定 GDI 对象、首帧耗时和空闲 CPU，不靠感觉。

这组数怎么来的

位图张数、item 数、定时器数、行高字号是设计直接决定的量，写死在 skin.json 里，可以做静态校验： 皮肤声明了 bitmaps: 3 却只给 2 个文件，安装时直接拒绝。

首帧、CPU、内存是运行时预算，落地后用两段脚本量：design/perf-bench.py 量首帧与每帧重绘， design/perf-probe.py 量空闲 CPU 与浮层成本。脚本已写好，但要在有显示的会话里跑——无桌面时窗口不映射， 重绘是空操作，量出来的数会骗人。

为什么不做第三档"更炫"

再往上就是背景壁纸、粒子、动态模糊——每一样都要整窗逐帧合成，代价是数量级上升， 对一个改两个开关就关掉的窗口没有意义。

皮肤分级只保留 minimal / standard 两级，rich 在规范里留了名字但暂不开放； 哪天真要做，必须先给出这张表的前三行数字。

Skin Spec

皮肤制作规范 v1

一份皮肤就是一个 zip（后缀 .wbskin），里面只有 JSON、位图和说明。 没有脚本、没有网络、没有注册表。下面是全部规则，写完照着校验就能装。

1 · 包结构

liquid-glass.wbskin
├─ skin.json          必需，唯一入口
├─ preview.png        必需，256×144，卡片缩略图
├─ README.md          可选，说明与作者
└─ assets/            可选，只允许 png
   ├─ backdrop.png
   ├─ mask.png
   └─ shadow.png

zip 根目录直接放 skin.json，不要套一层文件夹。 包内出现 .py .pyc .dll .exe .bat .ps1 任一后缀，安装器直接拒绝并留日志。

2 · skin.json 必需字段

{
  "id": "liquid-glass",        小写+连字符，装过不许改
  "name": "液态玻璃",
  "version": "1.0.0",          三段式
  "api": 1,                    皮肤 API 版本
  "engine": "bitmap",          bitmap | flat
  "performance": "standard",   minimal | standard
  "chrome": "custom",          custom | system
  "author": "WBOX",
  "metrics": { "row": 52, "font": 15, "icon": 22, "titlebar": 48 },
  "radius": { "window": 26, "card": 20, "row": 14 },
  "light": { ... },            必需，25 个 token
  "dark":  { ... }             可选，没有就复用 light
}

3 · 颜色 token（25 个，一个都不能少）

名字固定，含义固定，皮肤只改值。缺一个面板就回退到内置极简皮肤，并记一条 skin.invalid 日志。

# 文本四级
fg  t2  t3  t4
# 线 / 填充 / 按压
hair  hair_strong  fill  fill_2  press
# 卡片内凹与窗口底
inset  glass  glass_hi  glass_line  glass_edge
# 开关
switch_off  knob  on  on_knob
# 图标（应用图标与托盘）
icon_bg  icon_fg
# 浮层（菜单 / 行设置）
menu_base  pop_base
# 舞台（仅设计稿用，落地忽略）
amb0  amb1  amb2  amb3

4 · 性能分级

档硬限制
minimal位图 0 · 自绘元素 0 · 定时器 0 · 圆角 0 · 行高 ≤ 44
standard位图 ≤ 3 · 每行 item ≤ 6 · 定时器 ≤ 2 · 行高 ≤ 56

超过 standard 的限制只能申请 rich，而 rich 目前不开放安装。 分档不是荣誉，是给用户看的一句话：设置页那张卡片上会直接写「标准」或「最省」。

5 · 五条禁忌

  • 不带代码：皮肤不能执行任何东西，包括 eval 字符串和 __import__ 路径。
  • 不联网：安装与加载全程离线，图片也不能是远程 URL。
  • 不碰系统：不写注册表、不读用户文件、不改窗口属性以外的东西。
  • 不改布局语义：皮肤只改颜色、圆角、字号、行高；不改控件顺序、不隐藏功能、不加按钮。
  • 不超预算：位图长边 ≤ 2048、单张 ≤ 512 KB、包总大小 ≤ 4 MB。

6 · 校验与打包

# 校验（安装器与面板共用同一份实现）
python -m wingman.skincheck liquid-glass.wbskin
# 通过输出：ok id=liquid-glass api=1 tokens=25/25 engine=bitmap perf=standard

# 打包（把目录压成 .wbskin，根目录就是 skin.json）
python -m wingman.skinpack design\skins\liquid-glass -o dist\liquid-glass.wbskin

校验项固定为七条：zip 完整性、后缀白名单、skin.json 可解析、25 个 token 齐全、 位图尺寸与体积、性能档位匹配、id 不与功能插件重名。任一条不过就拒绝安装，并在 guard.log 留一行 skin.reject reason=...。

落地顺序建议：先做极简皮肤（原生控件、零位图，最快能跑通数据链路）， 再把手上的液态玻璃搬进 plugins/skins/liquid-glass/。 反过来做会把位图管线先钉死，之后想简化就得拆一遍。
